Reference assemblers

Four assemblers, released as drafts.

Reference implementations of the specification, one per language in the table below, each covering the four steps the spec gives the assembler (section 4): admit, resolve, fit, and render with a trace. They exist to prove the spec is buildable and to give conformance tests something to run against. Each is released at its repository's draft-release tag, the release that moves with the draft, and this page tracks their status against every requirement.

One row per requirement, one column per implementation. The scope says how much of a requirement an assembler can verify: assembler rows are fully testable in assembly, boundary rows are checked where the snapshot is handed over and the rest sits with producers or the application, and application rows cannot be observed during assembly, so they are documented rather than tested. Hover a row for what the assembler checks.

A row is implemented, or boundary-checked, only when tests exercise every clause in its scope and pass; both count toward the total above. Statuses are imported from the Python assembler's status.json. Each cell shows how many of the published cases exercising the requirement that implementation passes, from the conformance-report.json it publishes; a case changed since its run counts as not passing until it runs again.
