Reference assembler

In progress. No release yet.

A reference implementation of the specification, covering the four steps the spec gives the assembler (section 4): admit, resolve, fit, and render with a trace. It exists to prove the spec is buildable and to give conformance tests something to run against. This page tracks its status against every requirement and will grow into the API documentation once the API settles.

One row per requirement. The scope says how much of it an assembler can verify. Assembler rows are fully testable in assembly. Boundary rows are checked where items are handed over, and the rest of the obligation sits with producers or the application; the note says which part. Application rows cannot be observed during assembly, so they are documented rather than tested.

A row moves to implemented, or boundary-checked for boundary rows, only when tests exercise every clause in its scope and pass. Both count toward the total above. Statuses are imported from the Python assembler's status.json, where every claim cites the tests behind it; its own tests reject a claim while any case exercising it fails. Each implementation, Python and TypeScript, built independently from the spec, publishes a conformance-report.json that records the outcome of every published conformance case, and a row shows how many of the cases exercising it each one passes. A case counts only as it is now: one published, or changed, after an implementation's last run counts as not passing until it runs again, and the line above says how many have changed.

API · unreleased, subject to change

One call in, payload and trace out.

Producers run before assembly. The application authenticates each one, reads the clock once, and freezes everything that can affect the payload into a snapshot. assemble() receives only that snapshot, never producers, clocks or network access, so a stored snapshot replays to the same bytes (R-23). Nothing in it calls a model (R-18).

Each producer batch stays bound to the identity your application authenticated, which is what lets capability and state admission work (R-15, R-8). The Start page's assemble.py sketch shows the application side.

example.pyv0.0.1 · unreleased
from cwa import assemble, Snapshot from cwa.registry import Registry reg = Registry.from_json(lock, profiles, policies) # pinned by digest; an edit under the same version fails snapshot = Snapshot.freeze( # JSON-shaped, as snapshot.schema.json; SnapshotError rejects an invalid one batches=batches, # items + exclusions, one authenticated producer each capabilities=grant, # allow-list result for this route and user conflicts=groups, # conflict_group.schema.json scope=scope, # tenant, user, session, task assembly_time=now, # read once, before freezing route_policy=reg.route_policy("support-chat", "v1"), profile=reg.profile("policy-first-chat", 1, deployment=True), # evaluated only tokenizer="estimate-utf8/v1", # or your own: Snapshot.freeze(..., tokenizers={...}) renderer="cwa-messages/v1", # render IR for a provider adapter budget={"input": 8192, "reserved_output": 1200, "margin_percent": 15}, # headroom for an estimate ) result = assemble(snapshot) # pure: no I/O, clock or model result.payload # bytes, or None when the assembly is refused result.trace # dict matching trace.schema.json result.refused # bool · reason in trace.refused snapshot.digest() # context.snapshot_digest, the replay key
