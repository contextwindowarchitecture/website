# Context Window Architecture implementation guide

This is an integration guide, not a reference implementation or the full normative spec.
Use SPEC.md for numbered requirements, spec.html for definitions, and schema/ for JSON shapes.

- Assign each item one of the eleven slots in contract/slot-defaults.json and its allowed authority role.
- Render interaction.history as a transcript inside its wrapper, never as platform messages. Prior model turns carry lineage: generated and authority: untrusted.
- Use freshness for the observation timestamp and expires for the separate deadline; as_of is not a JSON alias.
- Keep instruction authority separate from factual precedence. Only governing and user authority may instruct; trust and injection_risk never change that, and evidence cannot direct behavior. Resolve facts only through explicit, versioned route policy for the same fact and scope, never by trust; escalate unresolved conflicts.
- The query always carries user authority. untrusted is allowed only in tool results, memory and history. Material a user pastes into the query renders with it, so delimit it in the body; supply material you receive separately as its own marked item.
- Supply typed conflict groups before assembly. Do not ask the assembler to infer contradictions from prose.
- Authenticate producer identity outside item fields. A source prefix never proves permission. A producer's kind bounds its slots whatever the route lists: state only from state producers, memory producers only to interaction.memory, retrieval and MCP producers only to the evidence slots. The one exception is a tool an MCP producer sends to governance.capabilities where the route lists that slot for it: it is excluded as capability_not_allowed, not producer_slot_not_allowed. Only the application capability policy admits tools; tool guards enforce invocation.
- Have producers return candidate items and excluded records. Report expired or revoked memory without re-emitting its body.
- Freeze items, variants, producer exclusions, conflict groups, producer context, capability allow-list, scope, assembly_time, policy, profile, tokenizer, renderer and budget before assembly. Do not call a model or read external state during assembly.
- Reject an invalid snapshot before assembly, with no payload and no trace (R-17). A valid snapshot satisfies schema/snapshot.schema.json and is I-JSON: no unpaired surrogates, and every number a finite double. No producer id heads more than one batch. Conflict group ids are unique, every id a group names is a candidate or a producer exclusion in the snapshot, no item is in two groups, and a fact group's fact is a key of the route's facts. A producer exclusion's duplicate_of or superseded_by names a candidate in its own batch. The profile's spec is cwa/draft, its route and route_policy_version equal the route policy's route and version, it places governance.instructions and interaction.query, and governance.output_contract when the route sets parser: true, and the snapshot's renderer can realize it.
- Fill and trace declared defaults. variants contains precomputed shorter bodies. eligibility is descriptive text, never code to execute.
- Count all rendered tokens, including wrappers, tool schemas and repeated slots. budget.input is the input ceiling after reserving output; do not subtract output twice.
- Provide the tokenizers fixture-whitespace/v1 and estimate-utf8/v1 and the renderers fixture-xml/v1 and cwa-messages/v1, as conformance/README.md defines them. Stop before assembly, with no payload and no trace, when an application supplies its own tokenizer under a published tokenizer ID or its own renderer under a published renderer ID (R-16). An application may declare its own tokenizer under an unused ID, but renders with a published renderer, and pairs an estimating tokenizer such as estimate-utf8/v1 with a budget.margin_percent that covers its error.
- Drop droppable items before reducing compressible items; then select variants or omit compressible items in the route's fitting-policy order (variants first when none is declared), tracing each omission as over_budget. A route may set a slot's min_tokens: under budget pressure never make a reduction that leaves the slot below it, freeze the slot once one is withheld, and refuse with slot_floor_over_budget if the payload still does not fit. A route may cap a slot with max_tokens; enforce it after token_budget caps and before budget pressure, whether or not the payload fits, by shedding that slot's own items in the same order, and refuse with protected_content_over_budget when its protected items alone exceed it. Keep protected items intact. A retriever that drops a near-duplicate reports it as an excluded record with reason duplicate_content, stage producer and duplicate_of naming the candidate it kept; carry it into the trace unchanged. When a route sets supersede: source on a slot, after resolving conflicts exclude each item for which the same authenticated producer sent an item with the same source and a later freshness (instants at full precision; ties all stay), as superseded with superseded_by. When a route sets dedupe: exact on a slot, after supersession exclude each item whose body equals a kept item's body once whitespace runs are collapsed and the ends trimmed (no Unicode normalization or case folding), as duplicate_content with duplicate_of; never exclude protected items or conflict-group members, and otherwise keep the highest-ranked copy. When a route sets max_per_source on a slot, after deduplication keep at most that many items per authenticated producer and source, protected and grouped items first and then the highest-ranked, and exclude the rest as source_diversity_cap. Only route policy raises a slot's tier; items claiming a higher tier are excluded with tier_upgrade_not_allowed. Profiles cannot omit admitted protected items or required slots.
- Refusal means no payload, result: null, included: [], compressed: [], and a reason. Success hashes the exact rendered UTF-8 bytes with SHA-256.
- Hand the payload to the model with each text in the platform role its renderer assigns, text assigned no role in a single user message where the query alone is the live turn, and no text of your own (spec section 1).
- Treat all provided example profiles as unevaluated drafts. Promotion needs a model version and a reproducible evaluation artifact.
- Schema validation alone is not conformance: an assembler's claim rests on a conformance report that passes every published case and rejects every published rejection (R-21, conformance/README.md).
