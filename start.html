Tool · steps 1 and 3

Prompt → slots migrator

Paste a system prompt, or a JSON array of chat messages. The migrator proposes a slot for each piece, assigns the slot's default authority, and lists the item fields it cannot fill in for you. Only text your application wrote is split by what it says: a user or assistant message, or a paragraph that starts "User:", "Customer:" or "Q:", keeps its speaker's slot however it is worded, because wording never earns authority. It is a heuristic: a system or developer message that matches no wording goes to governance.instructions, and any other piece it cannot place is left unassigned rather than guessed. It keeps each body whole, as assembly does, so delimit material a user pasted into their message inside that body, in a form the material cannot imitate (R-10). Nothing leaves your browser.

"No owner" counts the tokens the migrator could not assign to a slot, estimated as characters divided by four rather than counted by a published tokenizer. Every other item still needs a source, a source_version and a freshness before an assembler will admit it (R-2), a memory item an expires and a source naming its turn (R-9), and a knowledge item a relevance score (R-13). The migrator already sets governance items to trust: verified and marks the query, history, memory and evidence injection_risk: untrusted_content (R-10). Replacing every TODO is step 3, and it is the part no tool can do for you.
