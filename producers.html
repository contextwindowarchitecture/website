The producer contract

Building a tool an assembler can consume.

A producer is anything that emits candidate items into a slot: a retriever, a memory store, an MCP server, a state service, a policy loader, a capability policy. The assembler does not know how a producer works. It knows what the producer hands over. That handover is the contract. This page is a guide; the rules it cites are normative in the Spec.

The minimum item

Eight fields. Without them the assembler cannot place, rank, expire or trace the item, so it is refused at admission (R-2). Emit them on every item, every time, even when the value seems obvious.

Policy fields and slot defaults

Six more fields describe how an item may be handled. A producer that knows better than the slot default should set them. When it does not, the assembler fills them from the slot's defaults and the trace says so (R-3). These are the defaults the reference assembler ships with.

conflict_policy is applied only between items of the same authority tier. It is how two governing-tier items — an instruction and a steering example, say — resolve without inventing a tier for each.

Producer kinds

Five kinds cover almost everything. Each has one slot it normally feeds, one authority ceiling it may not exceed, and one rule that is most often broken.

Retrieval → evidence.knowledge
Packets with a score, never a blob.

One item per passage, each with its rerank score and source version. The retriever owns rewrite, retrieve, rerank; the assembler owns deduplicate, filter, packetize, budget, attribute. An empty result set is a valid, recorded outcome; do not pad it.

Ceiling authority: reference_only · R-13 · R-12
Memory → interaction.memory
State-vs-memory, as fields.

Every entry carries expires (the TTL), source (the turn it was derived from), lineage: summarised | generated, a revocation reference when the user has contradicted it, and trust: unverified. Expired or revoked entries are not emitted at all; the store filters, not the assembler.

Ceiling authority: generated · R-14 · R-9
State → state.user · state.task
Application-owned. Current or absent.

A state producer reads the database or the workflow engine and emits one item per fact, typed, with as_of set to the read time. It never derives a value from conversation. Claims the user made about themselves go to memory, not state.

Ceiling authority: state · R-8
MCP → tool_results · knowledge
Results to Evidence. Specs are proposed, not placed.

Tool results and resources become evidence.tool_results or evidence.knowledge with authority: observation or reference_only, an as_of, and untrusted by default. A resource that contains imperatives is still evidence. Tool specifications are proposed to the route's capability policy; the adapter never writes to governance.capabilities itself, and an item it emits there is refused with capability_not_allowed.

Ceiling authority: observation · R-15 · R-10
Capability policy → governance.capabilities
Application-owned. The only producer for this slot.

Holds the versioned allow-list of tools per route and user. Takes proposed specifications from MCP adapters and local tool registries, admits the ones this user may use, and emits one item per tool with authority: governing, source = the allow-list, source_version = allow-list version + specification content hash, trust: verified. Rejected proposals are reported to the assembler so they appear in the trace as excluded[] with reason capability_not_allowed. Permission is decided here, outside the model; the model is told what it may call, and the tool guard still enforces it.

Ceiling authority: governing · R-15 · R-5
Precomputed variants
Compression variants and reranker scores are the producer's job, computed before assembly and cached by content hash. The assembly step never calls a model (R-18). If your producer can offer a shorter form of an item, emit it as a variant on the item, not as a second item.
